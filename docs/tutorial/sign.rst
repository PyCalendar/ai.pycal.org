=================
Sign an agreement
=================

This tutorial is for contributors. A repository asks you to sign agreements
before your pull request is accepted, for example its AI policy. Signing takes
a minute and is done once for each version of an agreement, for all
repositories that ask for it.

1. Open your pull request on GitHub. In the checks, each agreement has an entry
   such as ``sign.pycal.org/ai-policy — @you: please sign AI Policy``. Select
   **Details**. It opens the signing flow of the pull request.
2. Select **Sign in with GitHub**. GitHub only tells the site who you are; it
   does not ask to let the site act on your behalf (when the site is set up
   with its OAuth app). Then the flow continues.
3. The flow shows one agreement after the other, required ones first, with your
   progress, such as *Agreement 1 of 2*. Nothing else on the page leads away;
   **About** at the bottom opens in a new tab. If the project offers choices,
   you choose one first.
4. Read the agreement, tick **I have read and accept this agreement**, type your
   GitHub handle and select **Sign and continue**. Optional agreements can be
   skipped with **Skip**; an agreement that becomes required later is asked
   again.
5. At the end, return to the pull request on GitHub, or view its page on the
   site.

The labels of your open pull requests and their checks are updated at once.
New pull requests are labelled when they are opened.

On the page of a single agreement, **Sign and open next agreement** signs it and
opens the next agreement of the project that you have not signed. If you signed
an earlier version, the page shows the changes in a second tab.

What you signed is listed on the page **My agreements**.

Why you type your handle and why there is no other way to sign is explained in
:doc:`/explanation/signing`.

When signing fails, the page names the error and links to its description in
:doc:`/reference/errors`.
